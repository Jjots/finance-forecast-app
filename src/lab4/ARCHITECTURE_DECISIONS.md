
# Архитектурные решения — ЛР №4

## 1. Система

Название: Finance Forecast System.

Назначение: анализ и прогнозирование финансовых показателей российских компаний.

## 2. Контейнеры системы

- web_app — React + TypeScript, разработчик Катя
- mobile_app — React Native, разработчик Катя
- backend — Python + FastAPI, разработчик Диана
- ml_service — Python, XGBoost, ARIMA, разработчик Диана
- db_main — PostgreSQL, разработчик Игорь
- dwh — TimescaleDB, разработчик Игорь
- queue — RabbitMQ, разработчик Даня
- scheduler — Apache Airflow, разработчик Даня

Использовать данные ID без изменения.
В новых диаграммах использовать backend, а не api_backend.

## 3. Внешние системы для L0

Проектируемые корпоративные интеграции:

- corp_iam — корпоративная система аутентификации
- corp_bi — корпоративная BI-платформа

Источники, предусмотренные в предыдущих лабораторных:

- rfsd_dataset — финансовая отчётность РСБУ (ИПП)
- cbr_api — API Банка России
- moex_api — API Московской биржи

На L0 Finance Forecast System изображается как единая система.

## 4. Динамические сценарии

Сценарий A — получение финансового прогноза:
пользователь → Web App → Backend → ML Service / DWH → Backend → Web App.

Основной путь: локальный кэш устарел, ML-сервис доступен.

Сценарий B — фоновые процессы:
- ежедневная загрузка данных через Scheduler и Backend в DWH;
- отдельная еженедельная задача переобучения через Scheduler, RabbitMQ и ML Service.

Все вызовы пронумеровать и указать протоколы.

## 5. Инфраструктура

- Устройства пользователей — браузер и мобильное приложение.
- Веб-узел — Nginx.
- Сервер приложений — Backend, Airflow, RabbitMQ.
- Отдельный ML-сервер — ML Service.
- Приватный сервер данных — PostgreSQL и TimescaleDB.
- Предусмотрены проектируемые реплики баз данных.

Серверные приложения размещаются в Docker на Linux VM.

## 6. Протоколы и порты

- Пользователи → Nginx: HTTPS, 443
- Nginx → Backend: HTTP/JSON, 8000 (внутренняя сеть)
- Backend → ML Service: REST/HTTPS, 8443
- Scheduler → Nginx → Backend: HTTPS/JSON, 443
- Scheduler / ML Service → RabbitMQ: AMQPS, 5671
- Backend → PostgreSQL: SQL/TCP + TLS, 5432
- Backend / ML Service → TimescaleDB: SQL/TCP + TLS, 5433 на хосте
- Внешние финансовые источники: HTTPS, 443
- IAM: OpenID Connect / OAuth 2.0 через HTTPS
- BI: REST/HTTPS

В публичной сети открыт только HTTPS-порт 443.
Остальные сервисы находятся в приватной сети.

## 7. Общие правила

- Использовать PlantUML + C4-PlantUML.
- Для связей использовать Rel(), без Rel_D, Rel_R и Rel_L.
- Не изменять утверждённые ID.
- Не добавлять новые внешние системы без изменения общего архитектурного решения.
- Не изменять предыдущие лабораторные.
- Все проектируемые интеграции и серверы описывать как планируемые, а не уже реализованные.
- Каждая диаграмма должна успешно компилироваться.
